### A. Migración aplicada (punto 3)

En Supabase → SQL Editor:

```sql
select
  (select count(*) from information_schema.tables
    where table_schema = 'public' and table_name in ('tareas', 'etiquetas', 'tareas_etiquetas')) as tablas,
  (select count(*) from pg_policies where schemaname = 'public') as politicas,
  (select count(*) from pg_proc where proname = 'guardar_tarea') as funcion_guardar;
```

Esperado: `tablas = 3`, `politicas = 3`, `funcion_guardar = 1`. Resultado: ⟨ ⟩

### Variables de producción (punto 4)

Deben existir: `KAIRO_ADAPTADOR=supabase`, `NEXT_PUBLIC_SUPABASE_URL`, `NEXT_PUBLIC_SUPABASE_ANON_KEY`.
No deben existir en Vercel: `SUPABASE_SERVICE_ROLE_KEY`, `KAIRO_PERMITIR_LOCAL`, `KAIRO_SECRETO_LOCAL`,
`KAIRO_DIRECTORIO_LOCAL`.

### B. Sin claves en el navegador (punto 7)

En la carpeta del repositorio, con tu `.env.local` (no se sube a Git):

```bash
set -a; . ./.env.local; set +a
npm run build
grep -rlF "$SUPABASE_SERVICE_ROLE_KEY" .next/static | wc -l            # esperado: 0
grep -rl "sb_secret_" .next/static | wc -l                             # esperado: 0
curl -s https://vibe-kairo-4.vercel.app/acceso | grep -cF "$SUPABASE_SERVICE_ROLE_KEY"   # esperado: 0
```

Si `.env.local` no tiene la service role key, el primer `grep` no aplica: anótalo así. Resultado: ⟨ ⟩

### C. HTTPS obligatorio (punto 8)

En Windows usa `curl.exe` en lugar de `curl`.

```bash
curl -sI http://vibe-kairo-4.vercel.app/acceso | head -5     # esperado: 308 y Location: https://…
curl -sI https://vibe-kairo-4.vercel.app/acceso | grep -iE "^HTTP|strict-transport-security"
```
